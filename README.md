# مدار CRM — المرحلة الحادية عشرة

نظام CRM عربي RTL متعدد الشركات. يبني فوق أساس الهوية والصلاحيات في المرحلة الأولى ويضيف إدارة العملاء المحتملين والعملاء وجهات الاتصال والتفاعلات والوسوم، مع كشف التكرار والتحويل والدمج واستيراد/تصدير CSV.

تضيف المرحلة الثالثة صندوق محادثات موحدًا تجريبيًا وخدمة عملاء وSLA وردودًا جاهزة وإشعارات وعقود تكامل للقنوات، مع طبقة Data Provider تسمح باستكمال البناء محليًا دون Supabase أو مفاتيح خارجية.

تضيف المرحلة الرابعة وحدة المبيعات وعروض الأسعار فوق المرحلة الثالثة: دليل خدمات وباقات، Sales Requests مرتبطة بـCRM والمحادثات، عروض متعددة البنود وإصدارات وSnapshots، حسابات Minor Units، موافقات داخلية، قوالب ومعاينة A4، وإرسال وقبول/رفض تجريبي فقط.

تضيف المرحلة الخامسة العقود وأوامر العمل فوق المرحلة الرابعة. وتضيف المرحلة السادسة فوترة وتحصيلًا تشغيليين داخليين: جاهزية دفعات العقود، Snapshots للفواتير، موافقات وإصدار داخلي، سندات قبض وتوزيعات ذرية، Credit/Debit Notes، أعمار الديون، كشف حركة العميل، ومتابعة التحصيل. لا يوجد General Ledger أو بنك أو دفع أو ZATCA أو إرسال خارجي. Supabase Adapter ما زال Stub، وMigration 007 عقد غير مطبق أو مختبر تكامليًا.

تضيف المرحلة السابعة الموردين والميزانيات والمشتريات والمصروفات وضبط تكاليف المشاريع: دورة المورد، طلبات شراء، RFQ داخلي، عروض ومقارنة وترسية، أوامر شراء، استلام دون مخزون، فواتير موردين داخلية مع 2-Way/3-Way Match، تكاليف تشغيلية، ETC/EAC وربحية بعملة واحدة. لا يوجد Accounts Payable Ledger أو Supplier Payments أو General Ledger أو Inventory أو أسعار صرف. Supabase Adapter ما زال Stub، وMigration 008 عقد غير مطبق أو مختبر تكامليًا.

تضيف المرحلة الثامنة إدارة تنفيذ المشاريع من العقد وأمر العمل: Project Charter وWBS وBaseline وجدولة وتبعيات وموارد وسجلات وقت وإنتاج وموقع وRFI وSubmittals وجودة وNCR وSnags وتقدم وEVM وتسليم وإغلاق داخلي. تبدأ المسارات من `/dashboard/projects`. لا يوجد Payroll أو Inventory أو General Ledger أو قبول/توقيع عميل حقيقي. Supabase Adapter للمرحلة Stub صريح، وMigration 009 عقد غير مطبق أو مختبر تكامليًا.

تضيف المرحلة التاسعة إدارة الأصناف ووحدات القياس والمستودعات والمواقع، وسجل مخزون مشتقًا حصريًا من الحركات المرحلة، وطلبات المواد والحجز والصرف والمرتجعات والتحويلات والجرد والتسويات والتالف وإعادة الطلب. تربط المواد بالمشروع وWBS والمهام وProduction Jobs، وتستخدم Moving Weighted Average كتقييم تشغيلي غير محاسبي. تبدأ المسارات من `/dashboard/inventory` وتظهر مواد المشروع في `/dashboard/projects/[id]/materials`. لا يوجد General Ledger أو Journal Entries أو Accounts Payable أو Supplier Payments أو MRP كامل. Supabase Adapter Stub صريح، وMigration 010 عقد غير مطبق أو مختبر تكامليًا.

تضيف المرحلة العاشرة إدارة الإنتاج والتصنيع للمشروعات: Product production profiles وBOM/Routing بإصدارات وSnapshots ثابتة، Work Centers، أوامر إنتاج وبطاقات تشغيل، MRP تشغيلي محدود مع Netting/Pegging، جاهزية المواد، جودة وإتمام واستلام المنتج الجيد في Inventory Ledger، هالك وإعادة تشغيل وتوقفات وتشغيل خارجي، Infinite Capacity Load، وتكلفة تشغيلية غير محاسبية. تبدأ المسارات من `/dashboard/production` ويرتبط إنتاج المشروع في `/dashboard/projects/[id]/production`. لا يوجد APS أو MRP II أو IoT أو Production/WIP Accounting أو Payroll أو GL. Supabase Adapter Stub صريح، وMigration 011 عقد غير مطبق أو مختبر تكامليًا.

تضيف المرحلة الحادية عشرة إدارة الموارد البشرية والقوى العاملة: Worker Master منفصلًا صراحةً عن User وOrganization Membership، هيكلًا وتاريخًا وظيفيًا مؤرخًا، تقاويم وورديات، حضورًا وتصحيحات، إجازات وLeave Ledger، Overtime تشغيليًا، تسوية Attendance/Timesheet/Job Card، تخصيصًا للمشروع والإنتاج، مهارات وشهادات وتدريبًا، Onboarding/Offboarding، أداءً تشغيليًا محميًا، وPayroll Readiness بالدقائق والوحدات فقط. تبدأ المسارات من `/dashboard/hr`. لا يوجد Payroll Engine أو مبالغ رواتب أو Payslips أو GOSI/EOSB/WPS أو بنك أو دفع أو GL. Supabase Adapter Stub صريح، وMigration 012 عقد غير مطبق أو مختبر تكامليًا.

## التشغيل المحلي دون Supabase

1. انسخ `.env.example` إلى `.env.local` واترك `DATA_PROVIDER=local`.
2. نفّذ `npm install` ثم `npm run dev`.
3. افتح `/dashboard/inbox` أو `/dashboard/sales`. الوضع المحلي يستخدم شركة وحسابات تجريبية فقط ولا يتصل بقنوات حقيقية.
4. استخدم قائمة «اختبار الدور» داخل الصندوق للتحقق من المالك وخدمة العملاء ومدير المبيعات والمشاهد.

مسارات المرحلة السادسة تبدأ من `/dashboard/billing`. بياناتها محلية تجريبية وغير دائمة، والمستندات المطبوعة داخلية وليست فواتير ضريبية معتمدة.

مسارات المرحلة السابعة تبدأ من `/dashboard/procurement`. بيانات الموردين والأسعار والحسابات Seed مصطنعة. كل RFQ وأمر شراء وسند وفاتورة مورد ومعاينة طباعة مستند داخلي تجريبي، ولا يثبت إرسالًا أو استلام أموال أو مخزونًا أو قيدًا محاسبيًا.

مسارات المرحلة التاسعة تبدأ من `/dashboard/inventory`. الرصيد لا يقبل تعديلًا مباشرًا، بل يشتق من الحركات المرحلة بعد الحجز. لإعادة ضبط البيانات التجريبية استدعِ `resetInventoryDemoRepository()` في اختبار معزول أو أعد تشغيل عملية التطوير. لا تطبق Migration 010 على مشروع حقيقي؛ عقود RPC فيها ترفض التشغيل صراحةً حتى يتم اختبارها تكامليًا.

مسارات المرحلة العاشرة تبدأ من `/dashboard/production`. لإعادة ضبط بيانات الإنتاج المصطنعة استدعِ `resetProductionDemoRepository()` أو أعد تشغيل عملية التطوير. اقتراحات MRP لا تُنشئ أمر شراء أو RFQ أو Release تلقائيًا. استلام المنتج التام يرحّل Good Quantity المعتمدة فقط إلى Inventory Ledger وبـIdempotency، ولا يرحّل Scrap أو Rework. لا تطبق Migration 011 على مشروع حقيقي.

مسارات المرحلة الحادية عشرة تبدأ من `/dashboard/hr`. بيانات العاملين والهوية والشهادات مصطنعة ومحجوبة وفق الصلاحية. لإعادة ضبطها في اختبار معزول استدعِ `resetHrDemoRepository()`. Export الخاص بـPayroll Readiness هو CSV تشغيلي للوحدات والدقائق ولا يعني راتبًا أو دفعًا أو قبول نظام خارجي. لا تطبق Migration 012 على مشروع حقيقي.

يفشل Local Provider في الإنتاج ما لم يضبط `ALLOW_LOCAL_DATA_IN_PRODUCTION=true` صراحةً. هذا المفتاح للاختبارات المعزولة فقط، وليس نشرًا حقيقيًا.

## التقنية

- Next.js 16 (App Router + Server Actions + Proxy) وTypeScript الصارم.
- Supabase Auth وPostgreSQL وRow Level Security.
- Tailwind CSS 4 وواجهة عربية متجاوبة.
- Zod للتحقق من مدخلات الخادم وVitest للاختبارات الآلية.

## التشغيل المحلي

1. ثبّت Node.js 22 أو أحدث ثم نفّذ `npm install`.
2. أنشئ مشروع Supabase محليًا أو سحابيًا.
3. انسخ `.env.example` إلى `.env.local` وأضف رابط المشروع و`anon key`. لا تضع `service_role` في متغير يبدأ بـ`NEXT_PUBLIC_`.
4. Migration المرحلة الرابعة `202608060005_phase_four_sales_quotations.sql` عقد مستقل غير مطبق. لا تطبقه إلا في مرحلة تكامل Supabase معتمدة وبعد النسخ الاحتياطي والمراجعة.
5. شغّل `supabase/seed.sql` ثم `supabase/seed_phase_two.sql` في بيئة تطوير معزولة فقط.
6. نفّذ `npm run dev` ثم افتح `http://localhost:3000`.

## تعدد اللغات

- الواجهة تدعم العربية والإنجليزية، مع العربية كلغة افتراضية.
- زر اللغة متاح في شاشات المصادقة ولوحة التحكم، ويُحفظ الاختيار في Cookie آمنة لمدة عام.
- يتبدل `lang` و`dir` على عنصر HTML بين RTL وLTR، وتستخدم التواريخ التنسيق المحلي حيث ترتبط بالبيانات.
- أسماء الشركة والعملاء والأدوار ومصادر ومراحل CRM تدعم حقولًا عربية وإنجليزية مع رجوع آمن إلى الاسم المتوفر.
- ملفات `src/lib/i18n` تعزل إعدادات اللغات والقاموس، ويمكن إضافة لغة جديدة دون تغيير نموذج الصلاحيات أو عزل الشركات.

## المصادقة وإنشاء الشركة

صفحة `/register` ترسل بيانات الشركة في User Metadata. المشغل `handle_new_user` ينشئ في معاملة واحدة: الملف الشخصي، الشركة، الإعدادات، الأقسام، العضوية، الأدوار الافتراضية، صلاحيات المالك، وسجل التدقيق. فعّل Email Confirmation من Supabase، وأضف روابط التحويل المحلية والإنتاجية إلى Auth URL Configuration.

## الدعوات

ينشئ المالك دعوة من `/dashboard/users/invite`. يُخزّن SHA-256 للرمز فقط وتنتهي الدعوة بعد 72 ساعة. في التطوير يظهر الرابط لاختباره. في الإنتاج يجب ربط مزود بريد موثوق وإرسال الرابط من خادم أو Edge Function؛ لا يعرض التطبيق الرمز في الإنتاج. عند التسجيل من الرابط يتحقق مشغل قاعدة البيانات من الرمز والبريد والصلاحية، ثم ينشئ العضوية والدور ويبطل الدعوة في المعاملة نفسها.

## استعادة كلمة المرور

تستخدم `/forgot-password` دورة Supabase الرسمية، برسالة محايدة لا تكشف وجود الحساب. أضف `/update-password` إلى Redirect URLs في إعدادات Supabase.

## وحدة CRM

- `/dashboard/crm`: مؤشرات المصادر والمراحل والمسؤولين والتحويل والمتابعات المتأخرة.
- `/dashboard/crm/leads`: جدول وKanban وبحث وفلاتر وPagination وأرشفة وتصدير.
- `/dashboard/crm/customers`: حسابات الأفراد والشركات مع جهات الاتصال والخط الزمني.
- `/dashboard/crm/contacts`: دليل مستقل يدعم جهة اتصال بلا شركة.
- `/dashboard/crm/settings`: المصادر والمراحل والترتيب والألوان والوسوم.
- `/dashboard/crm/leads/import`: معاينة CSV، كشف المكرر، تخطيه أو تحديثه أو إنشاؤه بعد التأكيد.

عمليات التحويل والدمج والاستيراد تنفذ داخل دوال PostgreSQL ذرية. لا يقبل التطبيق `organization_id` من النموذج؛ تستخرجه قاعدة البيانات من العضوية النشطة للمستخدم.

## المبيعات وعروض الأسعار

- `/dashboard/sales`: KPIs ومسار الطلب والعرض.
- `/dashboard/sales/catalog`: دليل الخدمات والتكاليف المحمية والباقات.
- `/dashboard/sales/requests`: الطلبات والبحث والربط مع العميل والمحادثة.
- `/dashboard/sales/quotations`: العروض والإصدارات والموافقات والإرسال التجريبي.
- `/dashboard/sales/quotation-templates`: قوالب آمنة عربية/إنجليزية.
- `/dashboard/sales/approvals`: قرارات الموافقات الداخلية.

الحسابات لا تستخدم Floating Point؛ الأموال BigInt Minor Units والكميات أجزاء من ألف. راجع `docs/PHASE_FOUR_CALCULATIONS.md`. Local Adapter تجريبي وغير دائم، وSupabase Adapter عقد مؤجل.

لإعادة ضبط بيانات المبيعات التجريبية، نفّذ Reload كامل للصفحة أو استدعِ `resetSalesDemoRepository()` في اختبار معزول. لا تستخدم بيانات Seed كبيانات إنتاجية.

## الأدوار الافتراضية في CRM

| الدور | صلاحيات CRM الافتراضية |
|---|---|
| مالك الشركة | جميع صلاحيات CRM داخل شركته |
| مدير النظام | جميع صلاحيات CRM دون صلاحية المالك العامة المحمية |
| مدير المبيعات | إدارة كاملة للسجلات والتعيين والتحويل والدمج والإعدادات |
| موظف المبيعات | السجلات التي أنشأها أو أُسندت إليه، دون الدمج والإعدادات |
| خدمة العملاء | عرض العملاء وجهات الاتصال وتحديثها وتسجيل التفاعلات |
| مسؤول التسويق | إنشاء وتحديث واستيراد Leads دون إدارة العملاء الحساسة افتراضيًا |
| المحاسب | عرض بيانات العملاء وجهات الاتصال فقط |
| المشاهد | عرض فقط دون كتابة أو استيراد أو دمج |

مالك النظام العام يُمثل بالحقل المحمي `profiles.is_super_admin` ولا يظهر بين موظفي الشركة. لا يمكن للمستخدم منح نفسه دورًا أو تعديل المالك الأساسي بسبب سياسات RLS.

## الاختبارات والبناء

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

اختبارات التكامل على مشروع Supabase معزول:

```bash
CRM_TEST_USER_A_EMAIL=... CRM_TEST_USER_A_PASSWORD=... \
CRM_TEST_USER_B_EMAIL=... CRM_TEST_USER_B_PASSWORD=... \
npm run test:integration
```

اختبارات التكامل التي تعتمد على Supabase تحتاج مشروع اختبار مستقل وشركتين تجريبيتين. قائمة التحقق والنتائج موثقة في `docs/TEST_REPORT.md`.

## هيكل المشروع

```text
src/app/                 الصفحات ومسارات المصادقة ولوحة الإدارة
src/components/          مكونات الواجهة المشتركة
src/lib/                 عملاء Supabase، إجراءات الخادم، التحقق والأمان
supabase/migrations/     مخطط قاعدة البيانات وRLS والمشغلات
supabase/seed.sql        بيانات تطوير غير حساسة
supabase/seed_phase_two.sql بيانات CRM تجريبية لشركتين
public/templates/        قالب CSV آمن وواضح
docs/                    المخطط والتقرير وقائمة التحقق
```

تفاصيل الصلاحيات وRLS والعمليات المركبة موثقة في `docs/PHASE_TWO_SECURITY.md`.

## الخدمات الخارجية المطلوبة

- مشروع Supabase ومفاتيح URL وAnon.
- SMTP مخصص أو مزود بريد للإنتاج لإرسال دعوات المستخدمين ورسائل التأكيد والاستعادة.
- نطاق إنتاج وإضافته إلى Site URL وRedirect URLs في Supabase.

لا توجد مفاتيح أو كلمات مرور حقيقية داخل المستودع.
