# معمارية المرحلة الرابعة

## الطبقات

1. `src/lib/sales/types.ts`: نموذج المجال والعقود.
2. `schemas.ts`: تحقق Zod وتعقيم المدخلات.
3. `calculations.ts`: مصدر واحد للحسابات المالية.
4. `repository.ts`: واجهة Repository، Local Adapter، وعقد Supabase المؤجل.
5. `seed.ts`: بيانات محلية صناعية لشركتين ومصفوفة صلاحيات.
6. `sales-workspace.tsx`: واجهة متجاوبة تستدعي Repository، دون احتواء قواعد الأمان الأساسية.
7. Migration 005: مخطط PostgreSQL/RLS وعقد الترقيم الذري المستقبلي.

ينشئ `provider.ts` Local أو Supabase Stub دون تغيير الصفحات، ويستخدم العرض التجريبي Singleton محليًا ليستمر التدفق بين صفحات App Router. حدود الشركة والصلاحيات والتحقق وإعادة الحساب والتصدير داخل Repository، وليست مسؤولية إخفاء الأزرار. المعاينة تقرأ Snapshot الحالية نفسها ولا تعيد إنشاء Seed مستقلًا.

الصفحات لا تعتمد على Supabase مباشرة، ولذلك يمكن تبديل مزود البيانات بعد تنفيذ `SupabaseSalesRepository` دون إعادة بناء الواجهات. في الوضع المحلي تبقى التعديلات داخل جلسة الصفحة؛ ليست قاعدة بيانات إنتاجية ولا تخزينًا دائمًا.

إنشاء الأرقام، الإصدار، الإرسال، الموافقة ورد العميل عمليات ذرية داخل Local Repository. في Supabase يجب تنفيذها فقط عبر RPCs تستخدم قفل صفوف، معاملات، Idempotency، وفحص `record_version`. لا توجد سياسات كتابة مباشرة في Migration 005.
