# أمان الفوترة والتحصيل

- كل قراءة وكتابة تتحقق من المستخدم والشركة والصلاحية؛ علاقات السند والفاتورة تفحص الشركة والعميل والعملة.
- لا يُوثق `organizationId` القادم من المتصفح في تنفيذ Supabase المستقبلي؛ يجب اشتقاقه من العضوية النشطة.
- Zod strict يمنع Mass Assignment. النصوص تنظف من أقواس HTML، والطباعة لا تستخدم HTML خام.
- BigInt Minor Units، Idempotency، Record Version، فصل المنشئ عن المعتمد، ومنع الحذف/التعديل بعد الإصدار.
- CSV يبدأ بـUTF-8 BOM ويحيّد `= + - @`. لا توجد بطاقة أو سر بنكي أو service-role أو بيانات حقيقية.

RLS وRPCs موثقة كعقود غير مطبقة؛ لا تعتبر حماية Supabase مكتملة قبل تنفيذها واختبارها على مشروع معزول.
