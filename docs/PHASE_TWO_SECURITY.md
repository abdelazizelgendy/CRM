# الأمان والصلاحيات — المرحلة الثانية

## الصلاحيات

| الوحدة | الصلاحيات |
|---|---|
| Leads | `leads.view/create/update/delete/assign/convert/merge/import/export` |
| العملاء | `customers.view/create/update/delete` |
| جهات الاتصال | `contacts.view/create/update/delete` |
| الإعدادات والتقارير | `crm.settings.manage`, `crm.reports.view` |

إخفاء القائمة والأزرار يعتمد على صلاحيات المستخدم الفعلية، لكنه ليس حاجز الأمان. كل قراءة وكتابة تُراجع مرة أخرى في RLS أو داخل RPC ذات `security definer` مع فحص `auth.uid()` والصلاحية والشركة.

## RLS وعزل الشركات

- RLS مفعل على جميع جداول المرحلة الثانية.
- `current_organization_id()` تستخرج الشركة من العضوية النشطة ولا تقبل معرفًا من المتصفح.
- `can_access_lead()` تقيد موظف المبيعات بالسجلات المنشأة بواسطته أو المسندة إليه.
- المفاتيح الخارجية المركبة `(id, organization_id)` تمنع IDOR والربط بين شركتين.
- لا توجد سياسة `DELETE` تشغيلية؛ الحذف من الواجهة أرشفة منطقية فقط.
- Viewer لا يملك صلاحيات كتابة، وبالتالي تفشل الكتابة في الواجهة والخادم وRLS.
- سجل التدقيق غير قابل للتعديل أو الحذف من المرحلة الأولى، وتم توسيعه لأحداث CRM والاستيراد والتصدير والإعدادات.

## العمليات الذرية

| الدالة | الضمانات |
|---|---|
| `convert_lead` | قفل Lead، فحص التكرار، إنشاء Customer وContact، نقل الوسوم والتفاعلات، منع التحويل مرتين، Audit |
| `merge_leads` | قفل السجلين، نقل التفاعلات والوسوم، حل القيم، أرشفة المكرر، Audit |
| `import_leads` | حد 500 صف، فحص كل صف، سياسة المكرر، تقرير النتائج، Audit داخل استدعاء PostgreSQL واحد |
| `archive_leads` | صلاحية الحذف المنطقي، نطاق الشركة والوصول للسجل |

## CSV

قالب الاستيراد في `public/templates/leads-import-template.csv`. التصدير يطبق الفلاتر وRLS وحد 10,000 سجل، ويحيّد الخلايا التي تبدأ بـ`=`, `+`, `-`, `@`, tab أو carriage return لمنع CSV Injection.

## اختبارات التكامل

`scripts/phase-two-integration.mjs` ينفذ على مشروع اختبار حقيقي: تسجيل مستخدمين من شركتين، إنشاء Lead، منع القراءة والتعديل عبر UUID من الشركة الأخرى، كشف التكرار ومنع التحويل مرتين. لا تستخدم حسابات إنتاج.
