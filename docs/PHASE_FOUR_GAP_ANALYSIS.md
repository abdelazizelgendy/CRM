# Gap Analysis — إغلاق المرحلة الرابعة

## الحالة عند الاستكمال

قاعدة الفرع هي `5628c2f` من `agent/phase-three-unified-inbox`. كان التنفيذ المحلي يتضمن النواة المالية وRepository محليًا ومسارات المبيعات وMigration غير مطبقة، وكانت البوابة القديمة 54/54. لم يكن هناك Commit أو فرع منشور أو PR.

## الفجوات التي أغلقت

- ربط البحث والفلاتر الفعلية بدل عناصر UI الشكلية: الرقم، العنوان، اسم العميل، الهاتف، البريد، الحالة، المسؤول، المصدر، الأولوية، العملة، الموافقة، تواريخ الإنشاء والانتهاء، نطاق القيمة، والمنتهي أو القريب من الانتهاء.
- ترتيب أحدث/قيمة/انتهاء، Pagination حقيقية، وحفظ الفلاتر والصفحة في URL.
- CSV آمن داخل Repository بعد Organization Scope وRBAC، مع UTF-8 BOM ومنع Formula Injection وعدم كشف التكلفة أو الهامش.
- استمرار Local Repository بين تنقلات العميل، بدل إعادة Seed عند كل صفحة.
- إنشاء خدمة وباقة، ومحرر عرض متعدد البنود يدعم الإضافة والنسخ والحذف وإعادة الترتيب والبند الاختياري والخصم والضريبة والرسوم والتقريب.
- إعادة الحساب في Application Service والتحقق من البنود باستخدام Zod، مع Optimistic Concurrency.
- ربط المعاينة بالحالة الحالية بدل Seed منفصل، وزر طباعة فعلي، وإخفاء البنود الاختيارية غير المحددة من نسخة العميل.
- استكمال القبول والرفض وطلب التعديل التجريبي، Timeline، Audit، Notifications، ومنع الرد على الإصدار المنتهي أو Superseded.

## منفذ لكن يحتاج بيئة خارجية

- عقد Supabase وMigration وRLS وRPC الترقيم موجودة لكن Migration غير مطبقة ولم تُختبر على PostgreSQL.
- Email/WhatsApp/PDF Server-Side وبوابة العميل والتوقيع والتكاملات الخارجية مؤجلة عمدًا؛ المتاح Demo وHTML Print فقط.

## غير مختبر بصريًا

تعذر الفحص البصري الفعلي: خادم Next بدأ بعد تجاوز خلل `uv_interface_addresses` بيئيًا، لكن `agent-browser` فشل في إنشاء daemon ولا يوجد Chromium أو Playwright أو Puppeteer مثبت. لم تُلتقط Screenshots، لذلك لا تُغلق بوابة الاعتماد البصري في هذه البيئة.
