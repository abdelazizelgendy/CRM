# سياسة الموافقات

يدعم النموذج موافقة متسلسلة أو متوازية، مع خطوات لدور أو مستخدم. Local Seed يطبق مدير المبيعات ثم المحاسب. يمكن ربط السياسة بالإجمالي والخصم والهامش والعملة وفئة الخدمة في Migration.

- يلزم إذن مستقل للإرسال للمراجعة أو الاعتماد أو الرفض أو التجاوز.
- لا يعتمد المنشئ عرضه بنفسه عند تفعيل الفصل.
- القرار Append-only ولا يمكن تغيير قرار مكتمل.
- التجاوز يتطلب `quotations.bypass_approval` وتعليقًا مسجلًا.
- بعد الاعتماد، التغيير ينشئ إصدارًا جديدًا ويجعل السابق `Superseded`.
- الإشعارات تحمل Dedupe Key.

الموافقات في هذه المرحلة محلية فقط. الاعتماد المتزامن الحقيقي يحتاج RPC بقفل صفوف واختبارات PostgreSQL.

يمنع إنشاء طلب Pending مكرر لنفس الإصدار، ويُرسل إشعار Deduped للمعتمد التالي عند الانتقال بين الخطوات. حالات الاعتماد والرفض وطلب التعديل والتجاوز تكتب Audit Log ولا تستبدل القرار السابق.
