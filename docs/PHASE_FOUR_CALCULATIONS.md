# الحسابات المالية والتقريب

Local Adapter يخزن الأموال كأعداد صحيحة `bigint` في أصغر وحدة، والكمية بأجزاء من ألف. لا تستخدم عمليات JavaScript العشرية في الحسابات الحساسة.

لا تقبل الإجماليات من المتصفح؛ `createQuotation` و`updateDraft` يعيدان الحساب عبر `calculateQuotation` بعد Zod. البنود الاختيارية غير المحددة لا تدخل الحساب أو نسخة العميل، والقيم السالبة أو النسب خارج 0–100% أو الدقة الزائدة تُرفض.

| العملة | المنازل |
|---|---:|
| SAR, USD, EUR, EGP | 2 |
| KWD | 3 |
| JPY | 0 |

## الترتيب المعتمد

1. `round(quantityMills × unitPriceMinor ÷ 1000)`.
2. خصم البند بنقاط الأساس، Half-Up.
3. الضريبة على صافي البند.
4. جمع البنود المحددة فقط؛ الاختياري غير المحدد خارج الإجمالي.
5. خصم العرض على الإجمالي الفرعي، مع خفض ضريبة البنود بالنسبة نفسها.
6. الرسوم المسماة وضريبتها.
7. تعديل التقريب الموثق.
8. الإجمالي النهائي والهامش المحمي.

صافي الإيراد للهامش = الإجمالي الفرعي − خصم العرض + الرسوم قبل الضريبة. هامش الربح = صافي الإيراد − التكلفة، ونسبة الهامش = هامش الربح ÷ صافي الإيراد. الضريبة وتعديل التقريب لا يدخلان هامش الربح.

المصدر الوحيد هو `calculateQuotation`. PostgreSQL المقترح يستخدم `numeric(20,3)`؛ يجب أن تطابق RPCs هذه السياسة قبل التكامل.
